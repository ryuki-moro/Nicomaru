# 戻る導線（Back Navigation）の調査

- 実施日: 2026-10-22
- 対象: ブランチ `feature/ui-p2-quick-fixes`（`76e8eea`）のソースコード
- 方法: コードの読解のみ。実機での操作はしていない（実機の挙動は [review.md](review.md) のスクショが根拠）
- きっかけ: [review.md](review.md) の高-3・中-3・中-4・中-5・低-3・低-8 が、どれも「戻る先」や「戻ったあとの知らせ」に関わっていたため、原因をまとめて調べた

## 結論

- 戻る導線をまとめる共通部品がない。パンくず・戻るリンク・操作後の戻り先は、画面ごとに URL を直接書いている
- `router.back()`／`history.back()` は `src` 全体で使っていない。戻る先はすべて固定の URL
- 戻った先で「◯◯しました」を伝える共通の仕組み（トースト、`?done=` など）がない。完了を伝えているのは、その場にとどまる画面の `notice` だけ
- そのため、戻る先と完了の知らせが画面ごとにばらばらになっている。上の6件の指摘は、どれもここから来ている

## 3. エラー画面と認証

### 3-1. エラー画面の出口

- `/error`（`src/app/error/page.tsx:56-58`）も `not-found`（`src/app/not-found.tsx:25`）も、ボタンは「ログイン画面へ戻る」（`/login`）だけ。ログイン中かどうかや、ロールでの出し分けはない
- ログイン中に `/login` を開くと、着地点へ送り返される（`(public)/login/page.tsx:56-57`）。押しても前に進めず、実際には出口がない（高-3）
- 404 の文言は「ログイン画面からお進みください」で、ログイン中の人には合わない
- ルートグループごとの `error.tsx`／`not-found.tsx` はない。`notFound()` はどこで呼んでも、ヘッダーもナビもないルートの `not-found.tsx` を出す

### 3-2. 権限がないとき・対象がないとき

扱い方が4通りに分かれている（低-8）。

| 扱い                                                               | 画面                                                                                                  |
| ------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------- |
| 理由を出さず、着地点へ戻す（`requirePageUser` → `landingPathFor`） | 案件登録・テンプレート・プラン種別・利用者管理・アーカイブ（ロール違い）                              |
| コードなしで `/error` へ送る（「一時的な問題」の文言になる）       | 案件詳細 `cases/[caseId]/page.tsx:101`、案件変更 `edit/page.tsx:54`、アーカイブ `archive/page.tsx:77` |
| `/error?code=403`／`?code=404` へ送る                              | 式場管理・利用状況（403）、準備シート・打ち合わせ記録（404）                                          |
| `notFound()`                                                       | フォロー記録・提出物確認の詳細・テンプレート編集・利用者変更・式場編集・新郎新婦の宿題詳細            |

- 設計の遷移図は「権限不足 → P04（エラー画面）」。一方 `requirePageUser`（`src/lib/auth/session.ts:121-142`）は、ロール違いを着地点へ戻すと決めている（コメントで、書き方を1つにそろえるためと説明している）
- 案件詳細が、権限外と不存在を区別せず `/error` へ送るのは意図的（存在を漏らさないため）。ただし、コードを付けていないので文言が「一時的な問題」になる。これは事実と違う（高-3）
- API が 403／404 を返したとき、画面は `/error?code=` へ移る（`src/lib/api/client.ts:156-157`）

### 3-3. ログインし直したあとの戻り先

- 未ログインで開くと `/login?next=<パス>` へ送られる（`src/middleware.ts:86`）。ログインすると `next` へ戻る（`LoginForm.tsx:139-145`、`safeNext` で自サイト内のパスだけを許可）
- `next` に入れているのはパスだけで、クエリは落ちる。たとえば `/cases?scope=archived` は `/cases` に戻る（middleware と `client.ts:153` の両方）
- ロールごとの着地点は `landingPathFor`（`session.ts:107`）に集めてある。ただ `(couple)/layout.tsx:16` だけは `/dashboard` を直接書いている

## 5. 改善の方針

戻る導線の決まりを、次のように定める。

1. **パンくずはグローバルナビの起点から始める**: プランナー側はダッシュボードから（system_admin の画面は、その着地点から）。共通部品 `Breadcrumbs` にまとめ、各画面の自前の記述をなくす
2. **操作が終わったら来た一覧へ戻り、戻った先で知らせる**: 知らせの文言は URL から受け取らない。決まったキーと対象 ID だけを受け取り、表示する文言は画面側で組み立てる（`/error` と同じく、偽の案内文を差し込めないようにするため）。`role="status"` で読み上げる
3. **「戻る」は来た画面へ戻す**: 新郎新婦の宿題詳細は、来た画面を `?from=` で受け取る。`router.back()` は使わない（URL を直接開いたときやリロード後に、外のサイトへ出てしまうため）
4. **エラー画面の出口は、ログイン中なら着地点にする**: 文言も「ログイン画面から」ではなく、ロールに合わせた行き先にする。対象が見つからないときは、コード付きで送る（`?code=404`）
5. **権限がないときの扱いを1つにそろえる**

### 決まりごとの実装

- 完了の知らせは `?reviewed=<提出ID>`／`?submitted=<宿題ID>` で ID だけを渡す。表示する文言は、移った先の画面が RLS の範囲内で引いた宿題名・案件番号から組み立てる。見えない ID や、状態が合わない ID では何も出さない
- `?from=` は決まったキー（`home`／`timeline`）だけを受け付ける。それ以外は宿題一覧へ戻す（`src/app/(couple)/mypage/tasks/taskLinks.ts`）

### 設計書との差

- **4-3 D02**: 設計書は「確定する・キャンセルとも K02 案件詳細へ」。グローバルナビの追加で提出物確認一覧から入る流れが主になったため、一覧へ戻すことにした（2026-10-22 決定）。基本設計書（.docx）は書き換えていないので、改訂のときに反映する
- **4-3 P04**: 設計書のボタンは「ログイン画面へ戻る」。ログイン中は着地点へ戻すボタンに替えた。未ログインのときは、これまでどおり
- **遷移図「権限不足 → P04」**: これまでは一部の画面だけが従っていたが、プランナー側はすべてこれに合わせた
