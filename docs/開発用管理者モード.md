# 開発用管理者モード

ログイン画面の「開発用adminで入る」ボタンから、メールアドレス・パスワードを入力せずに式場管理者として操作できます。

```powershell
npm run dev:admin
```

http://127.0.0.1:3000/login を開いてボタンを押してください。通常サーバーが起動済みなら `npm run dev:admin -- --port 3002` を使います。終了は Ctrl+C。

## アカウントと設定

`.env.local` の `NEXT_PUBLIC_SUPABASE_URL`、`NEXT_PUBLIC_SUPABASE_ANON_KEY`、`SUPABASE_SERVICE_ROLE_KEY` が必要です。初回起動で、seed.sql の式場に専用の `admin` アカウントを作成します。別の式場を使う場合は `--venue-id <UUID>` を指定します。

資格情報は Git 対象外の `.env.dev-admin.json` に保存し、次回も同じ専用アカウントを使います。このファイルは共有しないでください。プロジェクトや式場を切り替える場合は、先に旧環境の専用Authユーザーを Supabase の Authentication から削除してから、このファイルを削除し再起動します。削除対象のIDはファイルの `authUserId` です。既存利用者のパスワードや権限は変更しません。

起動スクリプトがサーバーにのみ渡す設定は `DEV_ADMIN_LOGIN_ENABLED`、`DEV_ADMIN_EMAIL`、`DEV_ADMIN_PASSWORD`、`DEV_ADMIN_AUTH_USER_ID` です。`.env.local` にこれらを設定する必要はありません。あわせて `APP_BASE_URL` を起動したURL（例: `http://127.0.0.1:3002`）で上書きします。更新APIの同一Origin検証が `APP_BASE_URL` を基準にするため、`.env.local` の値のままでは別ポートでログイン・ログアウトが拒否されるからです。

## 認証と権限

専用サーバーは `127.0.0.1` に限定して起動します。通常の `npm run dev` と本番環境では入口が無効です。専用APIは development、有効化設定、loopback Host、同一OriginのJSON POSTを毎回確認します。

サーバーで通常のSupabaseパスワード認証を行い、指定アカウントのプロフィールが `active`・`admin`・所属式場ありの場合だけCookieを発行します。トークンやパスワードは画面・API応答には返しません。RLS、管理画面の権限判定、ログアウトは既存の仕組みを使います。`admin` は式場単位の管理者で、全体管理の `system_admin` とは別の役割です。

## Service Role使用範囲の追加（基本設計書6-3-5 表6-4の開発用補足）

| 用途                      | 使用場所                | 必須条件                                                                                                                            |
| ------------------------- | ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `setup.development-admin` | `scripts/dev-admin.mts` | 本番起動拒否。既存の有効な式場に専用adminだけを作成。既存利用者を変更しない。プロフィール作成失敗時は今回のAuthユーザーを取り消す。 |

`/api/auth/dev-admin` は anon key と本人セッションを使い、Service Roleを使いません。

## 検証

通常の `npm test` で、本番・設定不足・別Originの拒否、admin以外へのCookie発行拒否、起動前の本番判定を検証できます。

専用サーバーを3002で起動したうえで、ブラウザの通し検証を実行できます。

```powershell
$env:APP_BASE_URL='http://127.0.0.1:3002'
$env:PLAYWRIGHT_SKIP_WEBSERVER='1'
$env:E2E_DEV_ADMIN_MODE='true'
npx playwright test tests/e2e/dev-admin-login.spec.ts
```

Playwright用ブラウザが未導入でChromeがインストール済みの場合は、実行前に `$env:E2E_BROWSER_CHANNEL='chrome'` を指定すると、PCとスマートフォン画面をChromeで確認できます。
