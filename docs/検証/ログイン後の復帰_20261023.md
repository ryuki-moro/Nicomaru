# #104 ログイン後の元画面への復帰：統合・検証

対象: `codex/resume-login-next`。最新のローカル `origin/main`（`b426e99`）に#123を加えた `cdab1ba` を基点とし、既存実装 `551a60f` を取り込んだ。#103のOTP期限変更は含めていない。

## 統合内容

- middleware、P01、OTP要求、クライアントの401処理が `src/lib/auth/next.ts` の規則を共用する。内部絶対パスと `tab`・`page` の安全な値だけを保持し、トークン類とフラグメントは引き継がない。
- ログイン成功後は検証済みの `next` を優先し、未指定・不正なら役割別の初期画面へ戻す。OTP要求の `emailRedirectTo` にも検証済みの戻り先を載せる。
- P01の競合は、現在の開発用管理者ボタンと式場管理向けパスワード表示を維持して解消した。進捗JSONの競合は#123を保持し、#104だけを追加して一覧を再生成した。
- 既存チェックアウトの未コミットE2E修正（初回登録後のOTP発行間隔待ち）を保持した。元チェックアウトは変更していない。
- 基本設計4-2・P01の改訂差分を [API・更新境界](../詳細設計/APIと更新境界.md) に反映した。基本設計DOCX原本への反映は残る。

2. ローカルのSite URLと `APP_BASE_URL` のホスト名を一致させ、Mailpitの実メール内の `redirect_to` に `next` があることを確認する。2026-10-15のStep 0記録は [Issueコメント](https://github.com/ryuki-moro/Nicomaru/issues/104#issuecomment-6183169219) にあるが、今回の再試験結果とは区別する。
3. WebKitの起動環境を整備してモバイルプロジェクトを再実行する。基本設計DOCXの改訂とレビュー後にmainへ統合する。

```powershell

```
