# Step8 招待状態の先読み：統合・検証

基点は#104・#105・#120・#121・#122・#123統合済みの `ea82d94`、作業ブランチは `codex/resume-invitation-peek`。専用Issueは検索で見つからず、ユーザーの直接依頼を対象にした。既存の `_isolated/email-invitations` から登録ページ・表示判定・Service Role用途・試験のStep8差分だけを取り込み、元チェックアウトは変更していない。

## 実装

P02の表示時、43文字base64url形式のトークンをSHA-256化し、`purpose=initial_registration` と併せて招待を照会する。不正形式はDBを参照しない。状態列と本人照合に必要な案件ID・相手区分だけを取得し、メール・氏名は取得しない。新たなService Role用途 `auth.invitation-peek` はソースの許可表へ追加した。共有の資格情報・DB grants・RLS・認証設定は変更していない。

| 状態                               | 表示・動作                                             |
| ---------------------------------- | ------------------------------------------------------ |
| 未使用                             | 登録フォーム。ログイン中なら表示名と本人登録を促す注記 |
| 使用済み                           | 登録済み案内と `/login?next=/mypage` へのリンク        |
| 使用済み、かつログイン中の本人     | `/mypage` へ移動                                       |
| 期限切れ・失効・該当なし・不正形式 | 無効案内とプランナーへの再発行依頼                     |
| 状態照会のDBエラー                 | 状態確認の失敗と開き直しを案内                         |

本人照合はactiveなcoupleだけを対象に、本人セッションのRLS経由で `user_profile_id`・`case_id`・`partner_role` の一致を確認する。スタッフ、同案件の別パートナー、別案件、案件紐付け前の利用者は本人として復帰しない。未使用なら本人ログイン中でもフォームを維持する。期限切れ・失効の不要な認証照会と、未使用招待の不要な所有者照会は、失敗する試験を確認してから省いた。

`force-dynamic` で表示を更新し、案件ID・相手区分・DBエラー内容はページやフォームpropsへ出さない。ページを開くだけでは招待を更新・消費せず、登録直前の状態変化は既存の初回登録APIが最終判定する。先読みは登録成功の保証ではない。初回登録API・RegisterForm・migrationは変更していない。

## 検証

- 全単体・PGlite試験1091件成功、実PostgreSQL用15件skip。新規の招待表示試験22件成功。型検査・lint・本番ビルドも成功。
- 未実装時の「不正形式でもフォームを表示する」を赤で確認してから統合。形式の長さ・文字種、ハッシュと用途の絞込み、状態列だけの取得、動的表示設定、使用済み本人の3条件照合、共用端末・紐付け前・スタッフ、DB障害の秘匿を検証した。
- ビルド版Next.jsをローカルの模擬Supabaseへ接続し、Chromiumの1280pxと390pxで、不正形式・未使用・使用済み・期限切れ・失効・該当なし・DBエラーを表示。同じURLを再読込し、未使用→使用済み→未使用の応答変化を反映することも確認した。
- 不正形式で模擬DBへの要求が増えないこと、他の14件がハッシュ・用途・取得列を限定したGETだけであること、更新・RPC・消費がないこと、HTMLに内部案件ID・DBエラーが含まれないこと、`Cache-Control` に `no-store` があることを確認した。

一時ブラウザー試験は `.codex-work/scratchpad/invitation-peek-browser.cjs`。ビルド・起動ともダミーURLと試験専用のキー文字列を使用し、共有環境の資格情報は使っていない。使用済み本人の復帰と共用端末の照合はServer Componentの単体試験で確認し、ブラウザーでは未ログイン状態を確認した。実Authのセッションと実RLSを通した本人照合を示すものではない。
