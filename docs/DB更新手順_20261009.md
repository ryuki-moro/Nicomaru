# 共有Supabaseへの新機能反映

今回追加した容量・監視・認証監査・監査保持には、20261009000100/000200/000300/000400/000600/000700の6本が必要です。

2026-10-09の読取確認では、既存の`venues`は参照可能でしたが、`usage_snapshots`と`system_alerts`は0件指定GETで`404 / PGRST205`でした。共有DBへの適用は未完了です。HEAD応答は不在の判定に使わず、GETで確認しています。

## 管理画面から適用する場合

1. `node scripts/prepare-observability-migration.mjs`で一括SQLを生成する。
2. 学校用プロジェクト`euinfogpqxfoorktzunh`のSupabase SQL Editorを開く。
3. `.env.venue-preview/追加migration適用.sql`の全体を新しいクエリへ貼り付け、DB所有者として一度実行する。
4. 最後の結果に`usage_snapshots`、`system_alerts`、`record_auth_failure(text,text)`が表示されることを確認する。
5. 新しいアプリを起動し、パスワードログイン、`/system`、内部集計の動作を確認する。秘密値や利用者情報をSQL結果の画像へ含めない。

SQLはトランザクション内で新しい定義と適用履歴を追加します。新テーブルが一部でも存在する場合は安全側に止まります。その場合は個別migrationの適用履歴を確認し、全体を無理に再実行しません。

定期処理登録の関数は更新しますが、関数の実行やジョブ登録は行いません。実データの削除・メール/LINE送信・AI処理も呼び出しません。

## CLIで管理している環境

通常どおり対象プロジェクトのmigration履歴を確認してから適用します。`supabase db reset`を共有DBへ実行しないでください。ローカルSupabase/CIでは新規作成時に全migrationが自動適用されます。

対象PCではブラウザー操作ツールが起動時の実行環境エラーで利用できず、共有DBを更新できていません。ソースのマージ・CIでの検証と、共有DBへの反映は別々に記録します。
