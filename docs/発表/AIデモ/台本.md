# AIデモ台本（約9分）

**伝えること**：プランナーの「読む・書く・訳す・まとめる」をAIが下ごしらえし、決めるのは人。AIは自宅PCのローカルLLMで動くので、ゲストの個人情報は外部のAIサービスへ出ない。

素材（このフォルダ）：

- `打ち合わせメモ.txt`：第1幕で貼る
- `ゲストリスト_石井家.csv`：第2幕で提出（わざと不備を入れてある）
- `BGMリクエスト_英語.txt`：第3幕で新郎新婦が提出

## 準備（本番の30分前まで）

構成：デモ画面とAIワーカーはこのPC、LLMは自宅PC。ワーカーは Tailscale 経由で、自宅PCの ai-agent-lab の LLM生成窓口（`llm_gateway.py`、8766番）を呼ぶ。窓口が models.yaml の最適化を当てて Ollama を呼ぶ。

1. 自宅PCで Ollama と LLM生成窓口を起動する（`自宅PC_LLM窓口プロンプト.md` を自宅PCのAIアシスタントに渡すと用意できる）。デモ中は、自宅PCの ai-agent-lab で大きいモデルを使う作業をしない（GPUを取り合って遅くなる）。
2. このPCでブランチを取得して依存を入れる：`git fetch && git switch demo/ai-showcase && npm ci`
3. ターミナル1：`npm run demo -- --reset`（データを初期状態に戻して 3105 番で起動）
4. ターミナル2（PowerShell）：
   ```powershell
   $env:OLLAMA_ENDPOINT='http://<自宅PCのTailscale IP>:8766'; $env:OLLAMA_API_KEY='<窓口の合言葉>'; $env:OLLAMA_MODEL='gemma3:12b'; npm run demo:ai
   ```
   - 「起動しました」と出ればつながっている。モデルの読み込みと、60分の保持もここで行う。
   - `--reset` でデモをやり直したときは、ターミナル2も起動し直す（合言葉が作り直されるため）。
5. 予行（モデルを温める）：プランナーで石井様以外の案件（例：青木様）を開き、「AIにサマリーを作り直してもらう」を1回押して、AIの要約に変わることを確かめる。
6. 画面を2つ並べる
   - 左（プランナー）：通常のウィンドウで http://127.0.0.1:3105/login →「パスワードでログイン（プランナー・管理者）」→「パスワードでログイン」（入力は空欄のまま）
   - 右（新郎新婦）：シークレットウィンドウ（ログインが混ざらないように）で同じURL →「確認コードを送信」。開発者ツールでスマホ幅（390px）にすると「スマホで見ている」感じが出る。

## 第1幕　打ち合わせメモ → AIが宿題を起票（2分）

1. 左：案件一覧 →「石井 健太・石井 結衣」→「打ち合わせ記録」
2. `打ち合わせメモ.txt` の中身を「メモ」に貼り、「記録して案を作る」
   > 「打ち合わせのメモを保存するだけで、AIが新郎新婦への宿題を拾い出します」
3. 「AIによる起票案（要確認）」に宿題案が並ぶ（AIの目安つき）。1〜2件に期限を入れて「この案を宿題として登録する」→「起票案を採用する」
   > 「期限はAIに決めさせず、目安を見てプランナーが決めます。AIは下ごしらえ役です」
4. 右：「宿題・提出物」を開くと、いま登録した宿題が届いている

## 第2幕　ゲストリストの不備をAIが指摘 → 差し戻し文もAIが下書き（3分）

1. 右：「ゲストリスト提出」→ `ゲストリスト_石井家.csv` を選んで「提出する」
2. 左：「提出物確認」→「ゲストリスト提出」の行を開く
3. 「AIによる一次チェック」：ルールが 未入力・形式・重複 の3件を即座に指摘
   > 「機械的に分かるものはルールで、AIが止まっていても必ず出ます」
4. 「AIに表記ゆれ・敬称を見てもらう」→ 氏名に付いた「様」、「株式会社／(株)」、「一丁目／1-」などをAIが行番号つきで指摘
   > 「人が見落としやすい“表記ゆれ”や“敬称”は、AIが疑いとして挙げます」
5. 確認結果で「不備あり」を選ぶ →「一次チェックの指摘○件を材料に下書きします」と出る →「AIに文面の下書きを頼む」
6. 行番号つきの丁寧な差し戻し文ができる →「下書きを採用する」→（必要なら一言直して）「確定する」
   > 「指摘を拾って、角の立たない文面まで。プランナーは確認して送るだけです」
7. 右：宿題を開き直すと「不備あり」と「プランナーからのご連絡」が届いている

## 第3幕　英語の要望をAIが翻訳 → 返事も英語で（2分）

設定：新郎様はオーストラリア育ちで、英語のほうが書きやすい。

1. 右：「BGMリクエスト」（不備ありになっている）→ `BGMリクエスト_英語.txt` の中身を「回答」に貼り「提出する」
2. 左：「提出物確認」→ 石井様の「BGMリクエスト」を開く。「AIによる分類」に「進行・演出」などが自動で付いている
   > 「届いた文章は、AIが種類ごとに自動で仕分けます」
3. 「AIによる翻訳」：翻訳する文面に英文が入っている。翻訳先を「日本語」にして「AIに翻訳を頼む」
   > 「英語の要望も、その場で日本語にして内容をつかめます」
4. 翻訳する文面を次の返事に書き換え、翻訳先を「英語」にして「AIに翻訳を頼む」
   > BGMのご希望ありがとうございます。入場・歓談・退場とも承知しました。乾杯の曲は、曲名が決まりましたらお知らせください。音源はこちらで手配いたします。
5. 「コメント欄に入れる」→ 確認結果「確認済」→「確定する」
   > 「返事は日本語で書くだけ。英語にするのはAIで、送る前に人が確かめます」
6. 右：宿題を開き直すと「確認済」と英語の「プランナーからのご連絡」が届いている

## 第4幕　担当交代の引き継ぎサマリー（1分）

1. 左：「石井」の案件詳細 →「AIによる引継ぎサマリー」→「AIにサマリーを作り直してもらう」
   > 「急な担当交代でも、ボタン1つで状況・決定事項・注意点がまとまります」

## 締め（1分）

- AIは自宅PCのローカルLLM（Ollama）。外部のAIサービスを使わないので、ゲストの個人情報がそちらへ出ない。
- AIの出力はすべて「要確認」。採用・登録・送信は人が決める。
- AIが止まっても、ルールによるチェック・辞書翻訳・手入力で業務は止まらない。

## 困ったとき

| 症状                                     | 対処                                                                                                                     |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| 「ただいまAI補助を利用できません」と出る | ターミナル2が動いているか確認。止まっていれば手順4を再実行                                                               |
| ターミナル2に「つながりません」と出る    | 自宅PCの Ollama と窓口（llm_gateway.py）が起動しているか、Tailscale がつながっているか、合言葉が合っているかを確認       |
| ターミナル2に `401` が並ぶ               | デモを `--reset` で作り直した後。ターミナル2を起動し直す                                                                 |
| 「AIが処理中」から進まない               | AIの出力が形式に合わず再試行待ちのことがある。画面を再読み込みし、もう一度依頼する（メモは再保存、チェックは同じボタン） |
| 翻訳が遅い・失敗する                     | 「辞書で翻訳する（AI不要）」で定型文だけその場で訳せる                                                                   |
| 遅い（1回30秒以上）                      | 小さいモデルに替えて手順4を再実行                                                                                        |
| 最初からやり直したい                     | ターミナル1を止めて `npm run demo -- --reset`、続けてターミナル2を起動し直す                                             |
