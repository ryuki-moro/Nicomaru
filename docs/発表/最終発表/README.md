# 最終発表の準備メモ

このフォルダーは、2027年2月の学校の最終発表・デモに向けた準備用です。[中間発表資料](../中間発表/README.md)を再利用し、実際の評価結果と制作の振り返りを加えます。発表実施・評価完了・学校への提出を記録したものではありません。本番運用開始は現在予定していません。

関連Issueは、資料・デモ準備 [#62](https://github.com/ryuki-moro/Nicomaru/issues/62)、発表実施 [#64](https://github.com/ryuki-moro/Nicomaru/issues/64)、実績付きWBS [#65](https://github.com/ryuki-moro/Nicomaru/issues/65) です。期限は[学校制作スケジュール](../../学校制作スケジュール.md)を参照し、前倒しで進めます。学校が指定する具体的な締切がある場合は、月末の目安より早い期限を優先します。

## 担当者が先に確定する項目

| 項目                             | 記入欄                            |
| -------------------------------- | --------------------------------- |
| 学校の発表日・提出期限           | 未共有                            |
| 発表・質疑の持ち時間             | 未共有。中間発表資料は暫定8〜10分 |
| 学校指定の提出形式・提出先       | 未共有                            |
| 発表者・デモ担当・質疑記録担当   | 未決定                            |
| 投影用端末・画面比率・接続方法   | 未確認                            |
| 最終資料名・対象commit・デモ環境 | 発表前に確定                      |

Agent AIの契約は不要です。編集可能なPPTX、発表原稿、用意した模擬環境、ブラウザ、表計算ソフトを使って担当できます。

## 中間発表資料から更新する内容

中間発表のPPTXを別名で保存して編集します。元のPPTX・原稿は履歴として残します。再生成する場合は中間発表フォルダーのREADMEに従い、新しいrevision名を使います。

| 内容                              | 最終発表までに加えるもの                     | 根拠                                            |
| --------------------------------- | -------------------------------------------- | ----------------------------------------------- |
| 課題・4つの利用者役割・操作の流れ | 制作の目的とデモで確かめる点を短く整理       | 詳細設計と実装画面                              |
| 実装の証拠                        | 発表に使う同じ版の画面・検査結果             | commit、PR、CI実行URL                           |
| AI補助と手動操作                  | 実モデルを使ったか、手動でどこまで操作したか | デモの記録と試験ID                              |
| 評価方法・未測定項目              | 実測した結果、条件、件数、限界               | [評価まとめ](評価まとめテンプレート.md)と原記録 |
| 10月〜2月の予定                   | 予定と実績の差、修正した点、残った課題       | WBS、Issue、再試験の証拠                        |
| 質疑応答                          | 中間発表で受けた質問と対応結果               | [質疑記録表](質疑記録表.md)                     |

試験成功数だけを導入効果に置き換えないでください。「自動試験の成功」「校内の模擬評価」「実際の式場での効果」は別の結果です。未実施・skip・失敗・対象外は、その状態と理由を残します。

## 準備する順序

1. [テスト仕様書の使い方](../../テスト/README.md)で対象試験を決め、メンバーが結果と証拠を記入します。評価値は原記録から転記し、確認者が照合します。
2. [メンバー向けデモと運用手順](../../メンバー向けデモと運用手順.md)の模擬データで、提出→不備指摘→再提出→確認の流れを同じ版で再現します。外部メール・LINEの実送信やAI推論の実行を、未確認のまま実績に含めません。
3. 学校の持ち時間に合わせて資料とデモを配分し、通し練習の実測時間を記録します。中間資料の約9分は想定であり、最終発表の実測時間ではありません。
4. 投影端末でPPTXを開き、フォント、文字切れ、図、画面比率を確認します。PDFと模擬画面の保存版も開き、通信が使えない場合の説明順を決めます。
5. 発表で使うPPTX・PDF・原稿・デモcommitを確定し、提出担当が学校の指定先へ提出します。提出日時・提出物・受付結果を記録します。
6. 当日は質問と回答を記録し、終了後に課題と[WBSの実績](../../WBS/README.md)を更新します。
