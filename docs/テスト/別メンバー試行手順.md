# 別メンバー向け・基本の通し操作

Issue [#59](https://github.com/ryuki-moro/Nicomaru/issues/59) の試行用です。作成者以外のメンバーが、Agent AIなしで手順を読み、詰まった箇所を記録します。人による試行は未実施です。

## 実装担当から受け取るもの

[結果記録票](別メンバー試行記録票.md)を試行ごとにコピーし、準備欄を埋めて渡します。秘密値は別のチーム内の受け渡し方法を使います。

- 検証するアプリのcommit（40桁）、アプリURL、DBの識別名、環境担当と連絡方法。資料のcommitも別に記録します。
- seed済みのローカルSupabaseと起動済みアプリ。準備方法は[環境の使い分け](../環境の使い分け.md)と[E2E環境手順](../../tests/e2e/README.md)。この試行にはローカルの模擬メール受信箱が必要です。外部メールが届かない共有環境では、2人目の初回登録を含む手順を完了扱いにしません。
- 同じ式場のplannerアカウント、プラン「少人数婚」とテキスト宿題「BGMリクエスト」。担当案件を作れることを環境担当が先に確認します。
- 未使用の模擬メールアドレス4個。例は `trial-<実施ID>-a-groom@nicomaru.test`、`trial-<実施ID>-a-bride@nicomaru.test` と、`a`を`b`に替えた2個。山田太郎・山田花子など架空名を使います。再試行時は新しい実施IDにします。
- planner・couple新郎・couple新婦用の独立したブラウザプロファイル3個。タブを3枚開くだけではセッションが分かれません。アドレスバーのホスト名はすべて統一します（通常 `127.0.0.1`）。
- AI workerの管理担当、停止・復旧方法、模擬メール受信箱URL（通常 `http://127.0.0.1:54324`）、証拠の保存先。

実施者はログインできることとメール受信箱を開けることを確認し、準備が欠ければ開始せず「保留」と理由を記録します。DB投入・リセット・worker停止は環境担当が行います。別の試行が同じ環境を使っていない時間に行ってください。

## 6手順

画面の文言は対象commitの実装を優先します。見つからない項目を推測して進めず、URL（秘密部分を除く）・表示・困った点を記録してください。手順1〜5を通常条件で1巡し、手順6では別の新規案件で1〜5をもう1巡します。

### 1. plannerで案件・宿題・招待を作る

1. planner用プロファイルで `/login` を開き、「パスワードでログイン（プランナー・管理者）」から受け取ったアカウントでログインします。
2. `/cases/new` を開き、挙式日は実施日から90日後、新郎・新婦氏名は架空名、主連絡先は新郎、連絡先メールは今回の新郎用模擬アドレス、連絡起点はメール、プラン種別は「少人数婚」として「登録する」を押します。
3. 「案件を登録しました」で案件番号と宿題割当数を記録します。標準seedの少人数婚は8件です。異なる場合は準備したプランとの差を環境担当に確認し、理由を記録するまで進めません。
4. 新郎・新婦それぞれの招待URLを対応するプロファイルへ一時的に渡します。URLは秘密なので記録票・証拠に写しません。「閉じて案件一覧へ」から案件番号を開き、宿題「BGMリクエスト」と進捗を確認します。

期待結果: 自分の担当案件が作られ、宿題と2人分の招待が得られます。案件番号・宿題件数・操作時刻を記録します。

### 2. 主連絡先のcoupleで登録・保存・提出する

1. 新郎用プロファイルで新郎の招待URLを開きます。「はじめての設定」で、手順1の連絡先と同じ模擬メール、架空名を入力し、同意欄を確認して「登録してマイページへ」を押します。標準の主連絡先経路ではコード確認なしで `/mypage` へ進みます。
2. `/mypage/tasks` で「BGMリクエスト」を開き、「回答」に `入場: Canon in D／歓談: ジャズ` と入力し「一時保存」を押します。「入力中の内容を保存しました」を確認します。一度一覧へ戻って開き直し、保存内容が残っていることも確認します。
3. 「提出する」を押し、一覧の同じ宿題が「提出済」になることを確認します。

期待結果: 登録、本人の下書き復元、提出ができます。一時保存と提出済の画面を記録します。

### 3. もう一方のcoupleで共有を確かめる

1. 新婦用プロファイルで新婦の招待URLを開き、別の新婦用模擬メールと架空名で同意・登録します。
2. 「ワンタイムコード」が表示されたら、模擬受信箱でその宛先・今回の送信時刻のメールを開き、最新の6桁を入力します。6桁入力で送信が始まるため確認ボタンを連打せず、`/mypage` への移動を待ちます。コードやメール本文を証拠に含めません。
3. `/mypage/case` の案件番号が手順1と同じであることを確認し、`/mypage/tasks` の「BGMリクエスト」を開きます。

期待結果: 同じ案件・宿題が「提出済」で、手順2の提出内容が見えます。下書きは本人専用であり、相手の下書き共有を期待しません。提出後の共有状態を確認します。

### 4. 不備指摘して再提出する

1. plannerで `/submissions` を開き、案件番号と宿題名が今回のものに一致する最新提出を開きます。「不備あり」を選び、コメントに `退場曲もご記入ください` と入れて「確定する」を押します。
2. 新郎で宿題一覧を再読み込みし、「不備あり」を確認して開きます。指摘コメントが見えることを確認します。
3. 回答を `入場: Canon in D／歓談: ジャズ／退場: 星に願いを` にして「提出する」を押します。
4. 新婦でも一覧を再読み込みして同じ宿題を開きます。

期待結果: 状態が「提出済 → 不備あり → 提出済」と変わり、両者が修正後の最新内容を見られます。初回提出・不備コメント・再提出をそれぞれ時刻と画面で残します。

### 5. 最新提出を確認して進捗と履歴を照合する

1. plannerで提出物一覧を再読み込みし、今回の案件・宿題の最新提出を開きます。修正後の回答と提出日時を確認してから「確認済」を選び、「確定する」を押します。古い提出を開いていた場合は確定せず戻ります。
2. 両coupleで宿題一覧を再読み込みし「確認済」を確認します。plannerの `/cases/<案件ID>` とcoupleの `/mypage/case` で完了数を照合します。対象宿題以外を操作していない標準seedの新規案件なら、確認前0件から確認後1件へ増えます。対応不要など他の変更があればその内訳を記録します。
3. 記録票の初回提出・指摘・再提出・確認済の順序と証拠を照合します。画面で見えないDB上の全履歴や最新フラグの一意性は、環境担当へ確認を引き渡します。画面だけで確認済みと記入しません。

期待結果: 最新の修正内容が確認済になり、同じ案件の進捗が一致します。ブックの履歴・最新1件の内部整合は、画面証拠だけでは完全に検証できない範囲として区別します。

### 6. AI停止時にも同じ通し操作を行う

1. 環境担当が、この試行専用環境の全AI workerを停止します（手動起動ならその端末でCtrl+C後、終了を確認）。停止時刻を記録し、最後の心拍から10分を超えるまで待ちます。Ollamaだけを停止してworkerの心拍を残す条件とは区別します。
2. plannerで既存案件の `/cases/<案件ID>/sheet` を再読み込みし、「ただいまAI補助を利用できません」とAI依頼ボタンが出ないことを確認します。停止を確認できなければこの手順は保留です。
3. 実施IDのメールを `b` 系へ変え、別の新規案件で手順1〜5を繰り返します。coupleの2プロファイルはログアウトしてから新しい招待を開きます。1巡目の招待・提出は再利用しません。AI生成やAI下書きは使いません。
4. 結果と停止中の証拠を記録し、環境担当が開始前のworker稼働状態へ戻します。開始前から停止していたなら停止を維持します。復旧確認時刻も記録します。

期待結果: AIが利用不可と表示された状態で、登録・提出・指摘・再提出・確認済まで手動で完了します。停止前の成功だけではこの項目を合格にしません。

## 記録と引渡し

不明点で作成者から助言を受けた場合、助言前の詰まりと助言内容を残します。「自力で実施」と「助言後に実施」を分けてください。未実施は結果欄を空欄にし、前提不足は保留、期待結果との差は不合格にします。

証拠は `docs/テスト/エビデンス/<実施日>/<実施ID>/` などチームで決めた場所へ置きます。案件番号・試験番号・時刻で結び、招待URL・認証情報・実在の個人情報を除きます。記録票は実施者が記入し、確認者が読んで不足を仕様書へ反映します。

ブックとの対応は TC-F-3-3-N（保存・提出・再提出）、TC-F-4-3-N（不備指摘・確認）を中心とする部分試行です。テキスト形式1件だけなので、file/select/none、異常系、内部履歴の整合まで含めたケース全体の合格を転記しません。残範囲を実施してからブックの判定を付けます。

Issue #59は、別メンバーが6手順を実施し、詰まった点の修正と再確認が終わってから完了にします。資料準備やAIによるコード照合だけでは閉じません。
