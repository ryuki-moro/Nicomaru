## 再現条件と修正

1. ローカル模擬環境を起動し、plannerAでcaseAに文字提出形式・必須の宿題を追加する。
2. タイトルを `招待状デザイン WeddingReception2027ABCDEFGHIJKLMNOPQRSTUVWXYZ`、期限を2027-05-20にする。
3. coupleAで宿題一覧を開き、320pxと390pxの幅で確認する。
4. 修正前は英数字がカードからはみ出し、状態バッジと矢印が右へ押し出される。横スクロールが発生する。
5. 一覧カード内のタイトル側の親を `flex-1` → `min-w-0 flex-1`、タイトルを `block text-base text-text-primary` → `block break-words text-base text-text-primary` にする。
6. 同じデータ、同じ幅で再確認する。タイトルは折り返され、バッジと矢印がカード内に収まる。

`min-w-0` でflex子要素の自動最小幅による拡張を抑え、`break-words` で改行のない文字列を折り返す。修正は新規に再現した一覧の表示問題1件のみ。

| 幅    | 修正前の文書scrollWidth | 修正後の文書scrollWidth | 修正前/後の英数字行scrollWidth           | 判定 |
| ----- | ----------------------: | ----------------------: | ---------------------------------------- | ---- |
| 320px |                   517px |                   320px | 488px → 262px（カードclientWidth=262px） | 解消 |
| 390px |                   532px |                   390px | 488px → 302px（カードclientWidth=302px） | 解消 |

日本語長文タイトルと短いタイトルも併せて確認し、修正前後で横はみ出しなし。画像の前後で一部の宿題が「提出済」なのは、文字提出の確認で模擬データを更新したため。

### ローカル開発環境の注意

当初の試行ではD1ローカルへの書き込み後に開発用の自動再読み込みが発生し、提出APIが200でも一覧への遷移待ちがタイムアウトすることがあった。この試行を成功として集計していない。最終試行は検証ブラウザーで `**/_next/webpack-hmr**` のWebSocketを閉じ、各画面の読み込み完了を待って実行した。同一条件を変更前後に適用し、アプリのコード・業務処理は変更していない。ブラウザーから外部originへの要求は遮断した。
