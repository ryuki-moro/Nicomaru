# テスト仕様書・校内模擬評価の使い方

[テスト仕様書_校内デモ.xlsx](テスト仕様書_校内デモ.xlsx) は、[Issue #59](https://github.com/ryuki-moro/Nicomaru/issues/59) に対応する編集用の仕様書です。コア44機能に正常・異常/境界の各2ケース、条件付き拡張5機能に対象外の理由、共通要件18ケースを割り当てています。合計111ケースです。実施結果はまだ記入していません。

## 試験を始める

1. 実装担当から、検証するcommit・アプリURL・模擬データ・役割別アカウントを受け取ります。本人が使うパスワードや認証リンクはExcel・Issue・スクリーンショットへ記載しません。
2. [環境の使い分け](../環境の使い分け.md) に従い、学校デモ用またはローカルの模擬環境を使います。データの投入/リセットは実装担当が接続先を確認して実施します。削除、保持期限、通知送信の異常系はブックに示す自動試験の模擬DB・模擬送信先を使います。
3. Excel等でブックを開き、「試験仕様」の対象commit・環境/ブラウザ・担当を入力します。「機能対応」で範囲を確認し、試験仕様のフィルターで担当の試験を選びます。
4. 前提・データをそろえ、記載順に操作します。別セッションが必要な場合は別ブラウザまたは別プロファイルを使います。新郎/新婦の共有確認は同じ案件に紐づく別アカウントで行います。
5. 実際の結果、実施日時、証拠、合格/不合格/保留/対象外を記録します。未実施は結果を空欄にします。確認者が証拠を読み、必要なら手順の不足を修正します。

開発用Agent AIは不要です。Excel、ブラウザ、用意済みの模擬データとコマンドだけで実施できます。アプリ内のAI機能を測定する場合は、チームのローカルLLM環境が必要です。LLMが使えない場合は当該生成試験を保留にし、AI停止時の手動操作試験を実施します。

## 基本の通し操作

1. planner役で担当案件を作成し、宿題と招待の作成を確認します。
2. couple役で模擬招待から登録し、宿題を一時保存して提出します。
3. 同じ案件のもう一方のcouple役で、最新提出と状態が共有されていることを確認します。
4. planner役で不備を指摘し、couple役で再提出します。
5. planner役で最新提出を確認完了にし、進捗と履歴を照合します。
6. AIを停止した状態でも同じ手動の通し操作が完了することを確認します。

管理者の操作はadmin、式場をまたぐシステム管理はsystem_adminで行います。利用者/式場作成やパスワード再設定の試験では、実際のメール送信先を使わず、ローカルの模擬メール受け口または自動試験のスタブを使います。

## コマンド試験の記録

リポジトリのフォルダーを開き、セットアップ済みの端末で実行します。

```powershell
npm run lint
npm run typecheck
npm test
npm audit --audit-level=high
```

個別試験はブックの「操作・コマンド」欄を使います。例えば監査保持の境界値試験は `npm test -- tests/db/audit.test.ts` です。DBテストの通常経路はPGliteを使うため、実際のSupabaseデータを削除しません。PostgreSQLの同時接続試験は別の専用検証DBが必要です。skipや未設定を合格へ読み替えず、対象ケースを保留として記録します。

## 証拠と再試験

- 保存例は `docs/テスト/エビデンス/2026-12-01/TC-F-3-3-N/` とし、操作前後の画面、試験ログ、対象commitを一緒に残します。実データ・トークン・メール本文の秘密リンクを含めません。
- 不合格時は再現手順・期待結果・実際の結果・環境・試験ID・証拠を不具合Issueへ記載します。
- 再試験は元の証拠を残し、証拠ファイル名へ `retry-01` 等を付けます。結果欄と実際の結果には再試験日と前回からの変更を残します。
- 「機能対応」の合格数は試験仕様から計算されます。1件だけ合格しても機能全体の完了になりません。全ケース合格は入力結果の集計であり、第三者の確認・学校提出が済んだことを意味しません。
- 条件付き5機能は現時点の必須44機能に含めません。学校の対象へ採用する場合に、実装に合う具体手順へ置き換えてから試験します。

## 校内模擬評価

「評価計画」に EVAL-01〜08 の実施方法を記載しています。「評価記録」は1評価につき5行を用意した入力欄です。必要に応じて表の行を追加し、記録IDを重複させずに採番します。基準値/期待値と実測値/判定は原記録、分母/分子と比率は集計に使います。行追加後は比率の数式も引き継いでください。

- 工数は同一シナリオの作業開始・終了を決め、従来の手順とアプリ操作を各3回測ります。結果に秒/分の単位を明記します。月間削減量はこの小規模測定から断定しません。
- 提出漏れは対象6件（未提出4、期限超過2）、非対象4件など正解を先に決めます。検知率の分母は既知の対象数、誤検知は別に記録します。期限遵守率は「期限内提出数/期限が到来した対象数」で分けます。
- リスクは人が先に低/注意/高を判断し、アプリ結果を後で開きます。後から人の正解をアプリへ合わせません。
- 使いやすさは独自5問です。「次にすることが分かった」「提出できた」「状態が理解できた」「エラーから戻れた」「また使いたい」を各1〜5で記録します。SUSスコアとは呼びません。
- AI不備検出は適合率を `TP/(TP+FP)`、再現率を `TP/(TP+FN)` とし、別行へ分母・分子を記入します。分類正解率・下書き採用率・起票採用率も別の行にします。分母0/未入力は未評価で、0%に置き換えません。
- 評価参加者は匿名IDで記録し、協力の可否を本人に確認します。今回の結果は学校内の模擬評価です。実際の式場で効果が実証されたとは記載しません。

ブックの数式はArtifact Toolで再計算し、空欄・比率・部分合格を確認済みです。学校で使うExcel等の版では、最初に「合格」を1行だけ入力して対応数が更新されることを確認し、入力を戻してください。学校指定の様式がある場合は、この内容を対応付けて転記します。
