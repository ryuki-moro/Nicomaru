# 役割と画面

4つの役割が、それぞれ何をする人で、どの画面を使うかの一覧です。
デモ（`npm run demo -- --reset`）では、ログイン画面のボタンからすべての役割で入れます。

| 役割           | 何をする人か                                   | ログイン後の最初の画面           | 使う画面                                                 | スクリーンショット     |
| -------------- | ---------------------------------------------- | -------------------------------- | -------------------------------------------------------- | ---------------------- |
| 新郎新婦       | 式の準備（やること）を提出する                 | マイページ                       | マイページ・やること・タイムライン・挙式情報・アカウント | 08〜10、12〜13、16〜20 |
| プランナー     | 担当する案件を進める                           | 案件一覧                         | ダッシュボード・案件一覧／詳細・提出物確認・通知履歴     | 02〜07                 |
| 式場管理者     | 自分の式場の案件と準備の仕組みを整える         | ダッシュボード（準備の残り）     | プランナーの画面すべて＋プランとやること・プランナー管理 | 33・34                 |
| システム管理者 | 式場と職員を管理し、システムが動いているか見る | ダッシュボード（式場ごとの状況） | ダッシュボード・式場管理・職員管理・利用状況             | 35〜37                 |

## システム管理者が見ないもの

システム管理者は案件を担当しないため、案件一覧・提出物確認・通知履歴はナビに出さず、
URL を直接開いても「このページは表示できません」になります。ダッシュボードと式場詳細には、
案件の件数だけを出し、案件の内容や新郎新婦の個人情報は出しません。

画面の入口で止めているだけで、案件まわりの API とデータの読み取り範囲（`src/lib/d1/cases.ts` の `scope`）は、
まだ system_admin を含んでいます。データの層でも外す場合は、基本設計書の権限の記述と
`docs/詳細設計/データ辞書と権限.md` の改訂と合わせて行います。

## よくある流れ

1. システム管理者が「式場管理」で式場を登録し、式場詳細の「式場管理者を追加」で式場管理者を招待する。
2. 式場管理者がダッシュボードの「準備の残り」に沿って、やること・プランを登録し、プランナーを招待する。
3. プランナーが案件を登録すると、選んだプランのやることが新郎新婦に割り当てられる。
4. 新郎新婦がやることを提出し、プランナーが「提出物確認」で確認する。
