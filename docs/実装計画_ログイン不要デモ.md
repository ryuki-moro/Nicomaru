# 実装計画: ログイン不要デモ

## 目的とスコープ
- 目的: アカウントや外部サービスの準備なしで、にこまるの主要導線を操作できる版を作成して起動する。
- 完了条件: `npm run demo` でローカル起動し、未認証のブラウザで案件の検索・詳細表示、新郎新婦の宿題提出、プランナーの確認・差戻し、ブラウザ内保存・初期化を操作できる。
- 対象外: 実データの取得、実メール・LINE送信、AI生成、アカウント作成、既存アプリの認証変更。
- 規模: 中。独立したデモ用サブシステム。

## 前提と制約
- Node.js 22以上とブラウザを使用し、新しい依存パッケージは追加しない。
- 架空の5案件を初期データに使い、変更は当該ブラウザのlocalStorageに保存する。
- 既存のステージ済み変更（`Nicomaru`、`Nicomaru-1`）は今回の変更に含めない。
- 利用者の「ログイン不要版を作成」と先行する起動依頼に基づき、計画後そのまま実装・起動する。

## 現状把握
- `src/middleware.ts` と各認証済み画面はSupabaseのセッションに依存する。
- `tailwind.config.ts` の配色・角丸と、既存模擬シナリオの氏名・プラン・宿題名を再利用する。
- 通常版の起動スクリプトは維持し、専用の`demo`コマンドを追加する。

## 設計方針
- `demo/`にHTML・CSS・ES modulesを配置し、Node標準HTTPサーバーで127.0.0.1:3100に配信する。
- 独立版を採用する。Next.jsの公開ページ案より認証コードへの影響が少なく、Supabaseや環境変数がなくても起動できる。
- プランナーと新郎新婦は画面切替で同じ架空データを操作する。保存データの破損や保存不可でも初期データまたはメモリ保存で継続する。
- 配信ファイルを固定し、外部接続を禁止するCSPを付ける。任意のファイルや環境変数を配信しない。

## 実装ステップ
### Step 1 — デモの画面・データ・起動機能
- 変更対象: `demo/`、`scripts/demo-server.mjs`、`package.json`。
- 内容: 5案件の初期データ、状態遷移と検証、ダッシュボード・案件一覧/詳細・宿題・新郎新婦ホーム、視点切替、初期化、localhost配信を実装する。
- 検証: JavaScript構文、状態遷移と不正保存データ、HTTPの配信範囲とメソッドを自動検証する。
- 依存: なし。

### Step 2 — 操作検証・起動・案内
- 変更対象: `tests/demo/`、`README.md`、本計画の検証結果。
- 内容: 本物のChromeで提出→確認→差戻し、保存/再読込、入力と空検索、初期化、モバイル表示、外部通信なしを検証する。
- 検証: 専用テストを実行し、ローカルサーバーを起動してブラウザでデモ画面を開く。
- 依存: Step 1。

## リスクと未確定事項
