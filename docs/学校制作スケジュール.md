## 期限と対象

- 対象は2026年10月〜2027年2月。前倒し可、後ろ倒し不可。登録上の月末は各月成果物の最遅目安で、学校が別途示す具体的な提出日・発表日があれば、その早い期限を優先する。
- 2月の本番は学校の最終発表・デモ。アプリの本番運用開始・実利用者のデータを預かる運用・常時稼働・商用移行は今回の予定に含めない。デモ/検証は匿名化・模擬データで行う。
- 月末のMilestoneは成果物を揃える最遅の月の目安。具体的な学校日程が未確定でも着手し、発表前に資料・デモ版を固定する。11月末まで中間発表の準備を待たない。

## Agent AIの利用を前提にしない分担

- 担当区分は作業開始時の目安。ユーザーはCodexで実装/自動化/雛形を準備できる。他メンバーの作業はAgent AIの契約を前提にせず、手順・入力素材・既存の例を使って手動で完了できる。手動実装できるメンバーがコードを担当することも可能。実担当者はチームで決める。
- **Codex使用可**: 優先修正・継続製造・最終コードの確定（#54/#55/#63）。実装担当は確認済みコード、コマンド、模擬データ、図の雛形を他メンバーへ渡す。
- **Agent AI不要**: テスト技法・AWS演習・テスト仕様書・試験実施・証拠整理・PowerPoint/原稿・発表・WBS。Issueに入力素材、作業手順、保存先、完了条件を記載した。既存の例や学校教材を読み、ブラウザ/既存コマンド/利用可能なOffice等で進められる。
- 詳細設計図 #50 は実装担当が技術的な雛形を用意し、他メンバーがコード・画面・設計の対応を確認して図を整える。中間発表資料 #51 は手作業で担当可能。
- Issueの担当区分は利用できる道具の目安であり、正式な担当者はまだ割り当てていない。手動で実装できるメンバーの参加も可能。
- アプリ内のローカルLLM補助と開発用Agent AIの契約は別のもの。#22ではデモ時の起動・停止と手動操作を確認する。メンバー個人のAgent AI契約は必要条件にしない。

## 今から残す記録

- WBS #65 の実績入力は10月から開始する。作業ID/Issue、実担当、予定・実績の開始/終了、本人が確認した作業時間、成果物、PR/commit、試験ID、確認者を記録し、2月に発表結果を追記して完成する。
- コード・テスト・資料・デモが参照するcommitを揃える。未実施/skip/失敗は成功にせず、不具合修正後の再試験記録を残す。
- AWS #57 は学校の課題・指定環境を確認してから演習を行う。現在のアプリをAWSへ移すことや有料運用開始を自動的な完了条件にしない。

## 既存Issueの整理

- #14 は発表・検証用環境、#24 は模擬データで再現できるデモ/テスト環境、#21 は学校内の模擬評価へ変更。#19は既存E2Eと負例確認を再利用する。
- #17（外部送信ドメイン）、#20（実データ運用の定期バックアップ/復元）、#25（商用・協力式場運用の利用条件/費用）は**将来運用**として学校のMilestoneから外した。
- 常時稼働、自動再起動、商用プラン移行、実利用者のデータを預かる運用は今回の学校発表の必須条件にしない。デモに必要な認可、秘密値管理、匿名データ、起動・再現手順は確認する。
- 既存の実証計画、作業記録、設計上の将来候補は履歴として残す。校内の模擬評価を実際の式場運用による効果として報告しない。

## 進捗の更新

正本は [implementation-progress.json](implementation-progress.json)。各項目の状態/根拠、対象月/最遅目安/担当区分を編集し、`node scripts/render-progress.mjs`で[実装進捗一覧](実装進捗一覧.md)を再生成する。Issue登録は成果物の完成を意味しない。月別項目は既存機能・下位作業を参照するため、項目数を全体の完了率に換算しない。
