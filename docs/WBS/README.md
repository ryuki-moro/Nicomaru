# 作業計画と実績WBS

[作業計画と実績.xlsx](作業計画と実績.xlsx) は、2026年10月〜2027年2月の31作業を記録するブックです。[Issue #65](https://github.com/ryuki-moro/Nicomaru/issues/65) と[学校制作スケジュール](../学校制作スケジュール.md)に対応します。2月の本番は学校の最終発表・デモです。本番運用開始の予定は含めません。

## 毎週入力すること

1. 自分の作業ID/Issueを確認し、予定開始と実担当を記入します。学校の実際の締切が月末より早ければ、最遅期限を早い日へ変更します。前倒しは可能です。
2. 作業を行った本人が実績開始・実績終了・確認済み作業時間を記入します。時間は休憩を除く本人の記録を使い、commit日時の差から計算しません。
3. 成果物、PR/commit/試験証拠、確認者を記入します。試験ならテスト仕様書の試験ID、発表なら実施記録を紐づけます。
4. 差戻し・再試験・保留・中止の理由を記録します。再作業を分けるときは `W-023-R1` 等の行を追加し、元の作業IDを理由欄へ残します。
5. 週末に確認者と実績を照合します。2月の最終発表後に発表実績と提出記録を追記し、学校指定形式で提出します。

黄色は入力欄です。最遅期限は学校の日程に合わせて編集できます。「期限差(日)」は実績終了−最遅期限で、負なら前倒し、正なら遅れ、未終了なら空欄です。「実績確認」は終了日が入っていても担当・証拠・確認者が欠ければ未確認を示します。作業時間が不明な場合は0にせず空欄のまま確認します。

## 入っている実績と空欄の意味

W-003/W-004 の2026-10-09は、削除バッチ修正と依存更新のコミットが作られた日です。「記録根拠」のcommitから確認できます。作業開始日、担当者の実作業時間、本人/第三者の確認は確認していないため空欄です。この2行の記録だけで10月の製造全体が完了したとは扱いません。

他の作業の終了日・作業時間は空欄です。「人間未実施」「将来予定」は、発表・AWS演習・実端末試験・模擬評価・本人実績記入など、実施記録が必要な作業を表します。資料やコードの雛形が用意できたことと、人が実施/確認したことは分けて記録します。

## 表を追加・提出するとき

- 表の末尾へ行を追加し、作業IDを重複させません。追加後は期限差/実績確認の数式が引き継がれたことを確認します。
- 日付はExcelの日付として入力し、`yyyy-mm-dd` 表示を保ちます。
- Agent AIは不要です。学校で利用できるExcel等とGitHubのIssue/PR画面を使って記録できます。
- 個人名以外の機密、パスワード、認証リンク、実在する顧客のデータは記録しません。
- 学校指定の形式は未提供です。ブックは編集可能な原稿であり、学校形式へ転記し本人確認を終えてから提出版とします。

作成時に数式再計算、未入力/部分入力、日付表示、全シートのレンダリングを確認済みです。学校のExcel等で開いた際にも、実績日を一時入力して期限差が更新されることを確認し、元へ戻してください。
