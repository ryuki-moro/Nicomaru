# 式場編集の動作確認

確認用に実装したのは、システム管理者が式場の名前・代表メール・利用状態を変更する機能です。
動作確認できる状態で実装をいったん止めています。以下の手順で確認結果を共有してください。

## 開く場所と確認対象

| 項目 | 内容 |
| --- | --- |
| アプリ | [http://127.0.0.1:3000](http://127.0.0.1:3000) |
| ログイン案内 | このPCの `.env.venue-preview/ログイン案内.md` を開く |
| 接続先 | ローカルで起動したアプリから、既存の検証用Supabaseに接続 |
| 操作対象 | ログイン案内で指定された、今回の動作確認専用の模擬式場 |
| 使用する権限 | システム管理者（system_admin） |
| 関連作業 | [Issue #54](https://github.com/ryuki-moro/Nicomaru/issues/54)、[実装計画](実装計画_式場編集.md) |

ログイン案内はGitの追跡対象外です。メールアドレス・パスワード・設定値をIssueや共有資料へ転載しないでください。
一覧に他の式場が表示されても、今回指定された模擬式場だけを操作します。
ブラウザーでは上記の `127.0.0.1` のURLを使ってください。

アプリに接続できない場合は、まず開こうとしたURLとブラウザーに表示された内容を共有してください。
ログイン案内の値を送る必要はありません。

## 操作して確認する

最初に模擬式場の名前・代表メール・「利用中」の状態を控えておくと、確認後に戻せます。
メールの入力には `venue-check@example.test` などの模擬アドレスを使えます。この編集操作ではメールを送信しません。

| 番号 | 操作 | 確認する結果 |
| --- | --- | --- |
| 1 | ログイン画面で「パスワードでログイン（プランナー・管理者）」を選び、ローカルのログイン案内の情報でログインする | 「利用状況・通知ログ」が開く |
| 2 | 「式場一覧」を押し、指定された模擬式場の式場コードを押す | 「式場の詳細・変更」が開き、現在の値が表示される |
| 3 | 「式場コード（変更不可）」を確認する | コードは表示されるが書き換えられない |
| 4 | 式場名を模擬の名前に、代表メールを模擬のアドレスに変え、「変更を保存」を押す | 「変更を保存しました。」が表示される。保存中は重ねて操作できない |
| 5 | ブラウザーを再読み込みする | 保存した名前・代表メール・利用状態が残っている |
| 6 | 「式場一覧へ戻る」を押す | 模擬式場の行に変更した名前と利用状態が表示される |
| 7 | もう一度詳細を開き、代表メールを空欄にし、「利用中」のチェックを外して保存する | 保存成功が表示される。再読み込み後もメールは空欄で、チェックが外れている |
| 8 | 一覧へ戻る | 模擬式場の状態が「停止中」になっている |
| 9 | 詳細を開き、式場名を半角スペースだけにして保存する | 式場名の直下とフォーム上部にエラーが出る。再読み込みすると直前に保存した名前が残っている |
| 10 | 正しい式場名の状態で、代表メールを `invalid-email` にして保存する | メールの直下とフォーム上部にエラーが出る。再読み込みすると直前に保存したメールの状態が残っている |
| 11 | 控えておいた名前・メール・利用状態に戻して保存する | 保存成功が表示され、再読み込みでも元の状態を確認できる |

「停止中」は式場の利用状態を示す項目です。所属ユーザーを一括ログアウトさせる機能は含みません。
式場管理者のアカウント変更は、既存の利用者管理で行います。

余裕があれば、ブラウザーの幅を狭めても入力欄・エラー・保存ボタンが読めて操作できるか確認してください。
実際のスマートフォンやSafariでの確認を行った場合は、端末名とブラウザーも結果に添えてください。

## 確認結果の残し方

Issueやこの作業のチャットに、次の内容を記録してください。スクリーンショットは模擬式場の画面だけにし、ログイン案内や秘密の設定値を含めないでください。

| 項目 | 記録する内容 |
| --- | --- |
| 確認日・確認者 | 実際に確認した日と担当者 |
| 環境 | PC／スマートフォン、ブラウザー名 |
| 結果 | 上の手順番号ごとの合格・不合格・未確認 |
| 気になった点 | 操作手順、期待した結果、実際の表示。可能なら画面の画像 |

ユーザーの操作確認は、実施後に完了とします。自動テストが成功していても、この欄の確認済みとは扱いません。

## 実装側で確認済みの範囲

2026-10-08時点で、式場編集に対する以下の検証が成功しています。

| 検証 | 確認結果 |
| --- | --- |
| API・入力・Originの単体テスト | 52件成功 |
| PGliteによるSQL・RLS検証 | 2件成功 |
| ブラウザーE2E | PC寸法のChromeで7件、スマートフォン寸法のChromeで7件、計14件成功 |
| 全体の単体・SQL/RLSテスト | 520件成功、実PostgreSQL専用の12件はローカルサーバーがないためskip |
| 静的検査 | ESLint・TypeScript・差分の空白検査が成功 |
| 表示と操作の追加確認 | 幅320px・100文字の式場名でも横方向のはみ出しなし。入力変更後は古い保存成功表示を消去 |

E2Eでは、保存・再読み込み・一覧反映、メールの消去、停止中、入力エラー、別OriginとOriginなしの拒否、変更不可の項目、対象なし、未ログイン・権限外、500応答後の再試行を確認しています。
専用の模擬データを使い、試験用データは試験後に清掃しています。ユーザーが操作する確認用の模擬式場は別に用意しています。

スマートフォン寸法のChromeによる試験は、実機のSafariやWebKitによる試験ではありません。実WebKitの確認は未実施です。

コードはセキュリティ・正しさ・性能・単純性の観点で、Codexによる独立レビューを実施しました。軽微な指摘2件は修正済みです。
外部の `review.py` は `httpx` がないため実行できず、この独立レビューで代替しています。
