## AIを使わないメンバーの確認手順

Agent AI、専用有料ツール、APIキーは不要。GitHubでMarkdown/Mermaidを閲覧し、ブラウザでSVG/PDFと模擬画面を並べる。修正提案はIssue #50へ「図番号・機能ID・画面ID・相違点」で記録する。

- [ ] 01〜03を使い、誰が・どの画面で・どの権限で登録/提出/確認するか説明する。
- [ ] 対応表の49機能/31画面を元DOCXと照合し、条件付き5件を別扱いにしていることを確認する。
- [ ] 04/05/07の状態名が画面文言とDB制約に対応することを確認する。
- [ ] 06のLINE上限・未構成・送信失敗が「送信済み」に見えないことを模擬画面で確認する。
- [ ] ERカードの主キー/外部キー、式場/案件境界をデータ辞書と照合する。
- [ ] 原本とPDF/SVGの文字切れ・矢印・用語を確認し、確認者と日付をIssueへ残す。

このチェック欄はチームレビューの未実施項目であり、自動作成時に完了扱いにしない。

## 再生成

Node.jsとプロジェクト依存を用意して、リポジトリルートで実行する。DB接続情報・実データは不要。

```powershell
npx tsx scripts/design/export-schema.mts
node scripts/design/generate-reference.mjs
python scripts/design/render-diagrams.py
```

PDF描画はReportLabと日本語Meiryoフォントを利用する。Windows以外はスクリプトのフォントパスを適切な日本語TrueTypeへ変更する。SVGはMeiryo/Noto Sans JP等のフォントを利用する。図の自動生成後はPDFをPNGへ描画し、全ページを目視確認する。

```powershell
pdftoppm -png -r 100 docs/詳細設計/詳細設計図.pdf tmp/design-review
```

検証記録: 初回生成で12ページのPNGを確認し、矢印方向と役割説明を修正。修正後も全ページを再描画して確認する。チーム原文レビュー、実機読み上げ、学校発表での読みやすさ確認は上の手順で別途行う。
