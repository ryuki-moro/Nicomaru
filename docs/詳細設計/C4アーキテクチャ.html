  • 結婚式の準備を、プランナーと新郎新婦で進めるための Web アプリ。
  • 画面とサーバーは 1 つの Web アプリ、データは Supabase、AI は別に動く。
  • 今回のブランチで、ログイン不要デモと開発用 admin ログインが加わった。
  • 未確認定期処理・LINE・メールが実環境で動くかは、コードでしか確かめていない。

前提・気をつけること

未確認まだ確かめていない

  • pg_cron と pg_net は「あれば登録する」作り。実環境で 8 件の定期処理が登録済みかは確かめていない。
  • ログイン用メールを Resend で送る設定は README の記載だけで、設定ファイルでは見つからない。
  • Vercel での公開は資料の記載だけで、配備の設定ファイルはリポジトリに無い。

推定推定していること

  • LLM の呼び出しに時間切れの設定が無く、生成が長引くと心拍が途切れて「利用不可」になり得る。
  • 準備シートの AI 下書きは、画面を開き直さないと結果が出ない場合がある。

事実前提（確かめた事実）

  • 宿題の提出・差し戻しでは LINE もメールも送らない。プランナーは画面を開いて気づく。
  • 外部へ送る主な場面は、招待の送付と毎朝の期限切れ通知。期限前の知らせはアプリ内だけ。
  • メールや LINE の鍵が未設定だと、送らずに成功として扱う。
  • AI の「利用不可」判定は画面を開いた時の 1 回だけ。開いたまま止まっても表示は変わらない。
  • AI ワーカーは専用ロールで DB に直接つなぎ、使える関数は取得・完了・心拍の 3 つだけ。
  • pgvector と RAG は設計書にあるが、コードにはまだ入っていない。
  • AWS のテンプレートは学校の演習用で、アプリからは使っていない。
  • AI モデルはコードの既定が gemma3:12b、設定例は軽い qwen2.5:7b。担当者が機器に合わせて選ぶ。
  • ログイン不要デモは外部と通信せず、データはそのブラウザの中だけに残る。
  • 開発用 admin ログインは、開発モードで専用ランチャーから起動した時だけ有効になる。
